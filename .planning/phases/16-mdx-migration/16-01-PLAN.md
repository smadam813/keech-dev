# Phase 16 Plan 01: MDX Migration to s.markdown()

## Objective

Switch from runtime MDX execution (`s.mdx()` + `new Function()`) to compile-time HTML rendering (`s.markdown()` + `dangerouslySetInnerHTML`), enabling removal of `unsafe-eval` from CSP.

## Context

- @velite.config.ts - current Velite config using s.mdx()
- @src/components/blog/mdx-content.tsx - current MDXContent using new Function()
- @src/components/blog/code-block.tsx - current CodeBlock with React-based copy button
- @src/proxy.ts - middleware with CSP including unsafe-eval
- @src/app/blog/[slug]/page.tsx - blog post page consuming MDXContent
- @src/app/projects/[slug]/page.tsx - project page consuming MDXContent

## Tasks

### Task 1: Create rehype plugin for role="list" and switch Velite to s.markdown()
type="auto"

Update `velite.config.ts` to:
1. Create a custom rehype plugin that adds `role="list"` to `<ul>` and `<ol>` elements (replacing the React component override approach)
2. Switch both posts and projects collections from `s.mdx()` to `s.markdown()`
3. The `mdx` config key with rehype plugins still applies to markdown processing in Velite

**Done when:** `npm run velite` succeeds and `.velite/posts.json` contains HTML strings (not JS function code).

### Task 2: Rewrite MDXContent to render HTML via dangerouslySetInnerHTML
type="auto"

Replace the current client-component MDXContent that uses `new Function()` with a server component that renders HTML via `dangerouslySetInnerHTML`:
1. Remove `'use client'` directive, React runtime imports, and `new Function()` code
2. Change the component to accept `html: string` instead of `code: string`
3. Render via `<div dangerouslySetInnerHTML={{ __html: html }} />`
4. Keep the MDXFallback component for error handling
5. Update blog post page and project page to pass `post.body` as `html` prop

**Done when:** Blog and project pages compile without errors using the new component.

### Task 3: Implement DOM-based copy button injection for code blocks
type="auto"

Since we can no longer use React component overrides for `<pre>` elements, implement a client-side script that:
1. Create a new `CodeBlockEnhancer` client component that runs after mount
2. Uses `querySelectorAll('pre')` to find all code blocks in the rendered HTML
3. Wraps each `<pre>` in a `div.group.relative` container
4. Injects a copy button that reads `code.textContent` from the sibling `<pre>`
5. Handles clipboard API and visual feedback (copied state)
6. Keep the existing CopyButton component or create a lightweight DOM version

**Done when:** Copy buttons appear on code blocks and successfully copy code to clipboard.

### Task 4: Update tests for new MDXContent
type="auto"

Update `mdx-content.test.tsx` to test the new HTML-rendering approach:
1. Test that valid HTML renders correctly via dangerouslySetInnerHTML
2. Test that the component handles empty/missing HTML gracefully
3. Remove tests that relied on `new Function()` behavior

**Done when:** `npm run test` passes with updated tests.

### Task 5: Remove unsafe-eval from CSP
type="auto"

Update the middleware CSP in `src/proxy.ts`:
1. Remove `'unsafe-eval'` from the `script-src` directive
2. Keep `'unsafe-inline'` (still needed for Next.js hydration scripts)

**Done when:** CSP header no longer contains `unsafe-eval` in script-src. `npm run build` succeeds.

## Verification

1. `npm run velite` compiles content successfully
2. `npm run build` completes without errors
3. `npm run test` passes all tests
4. No `new Function()` usage in the codebase for MDX
5. CSP no longer includes `unsafe-eval`

## Success Criteria

- All blog posts render with full content visible
- Code block copy button works on code blocks
- VoiceOver list elements have `role="list"` preserved
- No CSP violations with `unsafe-eval` removed
- MDXContent component no longer uses `new Function()`
