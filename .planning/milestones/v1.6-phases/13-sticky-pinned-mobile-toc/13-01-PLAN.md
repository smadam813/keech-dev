    Modify `src/components/blog/mobile-toc.tsx` — three changes:

    **1. Sticky positioning on outer wrapper (per D-01, D-02, D-03):**
    Change the outer div from:
    ```tsx
    <div className="lg:hidden mb-8">
    ```
    To:
    ```tsx
    <div className={cn(
      'lg:hidden mb-8',
      'sticky top-16 z-40 bg-background -mx-6 px-6 pt-2',
    )}>
    ```
    - `sticky top-16` = pins at 4rem below viewport top, directly under the fixed header (h-16)
    - `z-40` = above page content, below header (z-50) and mobile menu overlay
    - `bg-background` = opaque background prevents content showing through when pinned
    - `-mx-6 px-6` = extends background edge-to-edge to cover the article's px-6 padding
    - `pt-2` = small top padding for breathing room when pinned
    - `lg:hidden` already ensures this only applies below lg breakpoint (per D-02)

    **2. Auto-collapse on heading link click (per D-05, D-06):**
    Add an `onClick` handler to the `#mobile-toc-content` div using event delegation. Change:
    ```tsx
    <div
      id="mobile-toc-content"
      role="region"
      aria-label="Table of contents"
      className={cn(
    ```
    To:
    ```tsx
    <div
      id="mobile-toc-content"
      role="region"
      aria-label="Table of contents"
      onClick={(e) => {
        if ((e.target as HTMLElement).closest('a')) {
          setIsOpen(false)
        }
      }}
      className={cn(
    ```
    This uses event delegation to catch clicks on any `<a>` inside the TOC content region. When a link is clicked, the accordion collapses. The browser then handles the anchor navigation with smooth scroll natively via the existing anchor `href` values (e.g., `#heading-id`). The `TocList` component is NOT modified (per D-07 philosophy — keep it simple, shared with desktop).

    **3. Visual pinned indicator (per D-04 — Claude's discretion):**

No additional shadow needed — the existing shadow-brutal provides sufficient visual grounding when pinned. The `bg-background` on the outer wrapper already distinguishes pinned state by creating an opaque band. This satisfies D-04 without overdesigning.

    Extend `e2e/mobile-toc.spec.ts` with two new tests inside the existing `test.describe('mobile table of contents')` block:

    **Test 1: Sticky TOC visible after scrolling**
    ```typescript
    test('TOC toggle remains visible after scrolling down', async ({ page }) => {
      await page.goto('/blog')
      const firstPost = page.locator('a[href^="/blog/"]').first()
      await firstPost.click()
      await page.waitForURL(/\/blog\/.+/)

      const tocToggle = page.getByRole('button', { name: /contents/i })

      if (await tocToggle.count() === 0) {
        test.skip(true, 'No TOC on this blog post')
        return
      }

      // Scroll down significantly (past the TOC's natural position)
      await page.evaluate(() => window.scrollTo(0, 1000))
      await page.waitForTimeout(300) // allow scroll + sticky to settle

      // The TOC toggle button should still be visible (sticky)
      await expect(tocToggle).toBeVisible()
      await expect(tocToggle).toBeInViewport()
    })
    ```

    **Test 2: Auto-collapse after heading link click**
    ```typescript
    test('auto-collapses after heading link click', async ({ page }) => {
      await page.goto('/blog')
      const firstPost = page.locator('a[href^="/blog/"]').first()
      await firstPost.click()
      await page.waitForURL(/\/blog\/.+/)

      const tocToggle = page.getByRole('button', { name: /contents/i })

      if (await tocToggle.count() === 0) {
        test.skip(true, 'No TOC on this blog post')
        return
      }

      // Expand TOC
      await tocToggle.click()
      await expect(tocToggle).toHaveAttribute('aria-expanded', 'true')

      // Click a heading link
      const firstLink = page.locator('#mobile-toc-content a').first()
      await firstLink.click()

      // TOC should auto-collapse
      await expect(tocToggle).toHaveAttribute('aria-expanded', 'false')
    })
    ```

    Add these two tests after the existing `'heading link navigates to section'` test, inside the same `describe` block. Keep all existing tests unchanged.
