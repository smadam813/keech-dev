Create a new `'use client'` component at `src/components/blog/filtered-post-list.tsx` that owns the blog filter state via `useSearchParams` and renders the FilterBar + post card grid.

**Imports:**
- `useSearchParams`, `usePathname` from `'next/navigation'`
- `useCallback`, `useMemo` from `'react'`
- `FilterBar` from `'@/components/ui/filter-bar'`
- `TagChip` from `'@/components/blog/tag-chip'`
- `PostCard` from `'./post-card'`
- `ListingViewCounts` from `'./listing-view-counts'`
- `ScrollReveal` from `'@/components/ui/scroll-reveal'`

**Props interface:**
```typescript
interface FilteredPostListProps {
  posts: Array<{
    title: string
    slug: string
    date: string
    description?: string
    excerpt: string
    tags: string[]
    readingTime: number
  }>
  allTags: string[]
}
```

**Implementation:**

1. **Read filter state from URL:** Use `useSearchParams()` to read the `tags` param. Parse comma-separated values into a `Set<string>` via `useMemo`:
   ```typescript
   const activeTags = useMemo(() => new Set(
     searchParams.get('tags')?.split(',').filter(Boolean) ?? []
   ), [searchParams])
   ```

2. **Stable slugs for view count fetching:** Memoize all post slugs (not filtered) so ListingViewCounts fetches counts once regardless of filtering:
   ```typescript
   const allSlugs = useMemo(() => posts.map(p => p.slug), [posts])
   ```

3. **AND logic filtering:** When activeTags is empty, show all posts. Otherwise, filter posts that contain ALL selected tags:
   ```typescript
   const filteredPosts = activeTags.size === 0
     ? posts
     : posts.filter(post => [...activeTags].every(tag => post.tags.includes(tag)))
   ```

4. **URL update helper:** Create a `useCallback` that writes the new tag set to the URL via `window.history.replaceState`. Sort tags alphabetically for consistent URL representation. Delete the `tags` param entirely when no tags are selected (clean URL):
   ```typescript
   const updateURL = useCallback((next: Set<string>) => {
     const params = new URLSearchParams(searchParams.toString())
     if (next.size === 0) {
       params.delete('tags')
     } else {
       params.set('tags', [...next].sort().join(','))
     }
     const query = params.toString()
     window.history.replaceState(null, '', query ? `${pathname}?${query}` : pathname)
   }, [searchParams, pathname])
   ```

5. **Toggle handler:** Create `handleToggle` callback that adds/removes a tag from the active set and calls `updateURL`.

6. **Clear handler:** Create `handleClear` callback that passes an empty Set to `updateURL`.

7. **Render structure:**
   ```
   <ListingViewCounts slugs={allSlugs}>
     <FilterBar
       items={allTags}
       activeItems={activeTags}
       onToggle={handleToggle}
       onClear={handleClear}
       renderChip={({ item, active, onToggle }) => (
         <TagChip key={item} tag={item} active={active} onToggle={onToggle} />
       )}
       label="Filter by tag"
     />
     {filteredPosts.length > 0 ? (
       <div className="grid gap-6 md:grid-cols-2 lg:grid-cols-3">
         {filteredPosts.map(post => (
           isFiltering ? (
             <PostCard key={post.slug} post={post} />
           ) : (
             <ScrollReveal key={post.slug}>
               <PostCard post={post} />
             </ScrollReveal>
           )
         ))}
       </div>
     ) : (
       /* empty state */
     )}
   </ListingViewCounts>
   ```

8. **Empty state:** When `filteredPosts.length === 0` AND `activeTags.size > 0`, render a centered empty state:
   ```html
   <div className="text-center py-12">
     <p className="text-muted text-lg mb-4">No posts match the selected tags.</p>
     <button
       type="button"
       onClick={handleClear}
       className="text-accent hover:text-accent-hover font-mono font-bold underline underline-offset-2 transition-colors"
     >
       Clear filters
     </button>
   </div>
   ```

9. **ScrollReveal bypass:** Compute `const isFiltering = activeTags.size > 0`. When filtering is active, render `PostCard` directly without `ScrollReveal` wrapper. When no filters active (initial load), wrap with `ScrollReveal` for entrance animation. This prevents re-triggering entrance animations on every filter change.

**Critical constraints:**
- `ListingViewCounts` MUST wrap both FilterBar and the card grid. Pass `allSlugs` (all published post slugs), NOT filtered slugs. This ensures view counts are fetched once and available for any card that appears after filtering.
- Use `window.history.replaceState` (NOT `router.replace()` or `router.push()`). This is a lightweight URL update that Next.js intercepts and syncs with useSearchParams. It avoids triggering server component re-renders.
- The `renderChip` callback in FilterBar must include `key={item}` on the TagChip to satisfy React's list rendering requirements.

**Final page structure:**
```tsx
import { Suspense } from 'react'
import { posts } from '@/.velite'
import { FilteredPostList } from '@/components/blog/filtered-post-list'
import type { Metadata } from 'next'

export const metadata: Metadata = {
  title: 'Blog',
  description: 'Technical articles, tutorials, and thoughts on software development, web technologies, and the craft of building things.',
}

export default function BlogPage() {
  const publishedPosts = posts
    .filter(post => !post.draft)
    .sort((a, b) => new Date(b.date).getTime() - new Date(a.date).getTime())

  const allTags = [...new Set(publishedPosts.flatMap(p => p.tags))].sort()

  return (
    <section className="w-full mx-auto max-w-7xl px-6 pt-12 pb-16">
      <h1 className="font-display text-4xl md:text-5xl font-bold mb-10">Blog</h1>
      <Suspense>
        <FilteredPostList posts={publishedPosts} allTags={allTags} />
      </Suspense>
    </section>
  )
}
```

**Critical constraints:**
- Do NOT add `'use client'` to this page. It MUST remain a server component for static generation.
- The `<Suspense>` boundary MUST be in this server component, NOT inside FilteredPostList. This isolates the useSearchParams call so only the filter area client-side renders.
- No `fallback` prop on Suspense (empty fallback). With 3 posts, hydration is near-instant. An empty fallback produces less CLS than a mismatched skeleton.
- Do NOT use the `searchParams` page prop. It is a Promise in Next.js 16 and accessing it opts the route into dynamic rendering.
