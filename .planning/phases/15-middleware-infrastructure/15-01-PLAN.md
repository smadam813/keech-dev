# Phase 15 Plan 01: Centralize Security Headers in Middleware

## Objective

Move all security headers from `next.config.ts` `headers()` to a new `src/middleware.ts` file, eliminating duplication and enabling future per-request header customization (e.g., nonce-based CSP if static generation constraint is ever relaxed).

## Context

- @next.config.ts — current `headers()` with CSP, X-Frame-Options, X-Content-Type-Options, Referrer-Policy
- @src/app/ — App Router pages (all statically generated)

## Tasks

### Task 1: Create middleware with security headers
type="auto"

Create `src/middleware.ts` that:
1. Imports `NextResponse` and `NextRequest` from `next/server`
2. Clones the response via `NextResponse.next()`
3. Sets all four security headers on every response:
   - Content-Security-Policy (same directives as current next.config.ts)
   - X-Frame-Options: DENY
   - X-Content-Type-Options: nosniff
   - Referrer-Policy: strict-origin-when-cross-origin
4. Exports a `config` with matcher that excludes static assets and Next.js internals

**Done:** `src/middleware.ts` exists with all headers set.

### Task 2: Remove headers() from next.config.ts
type="auto"

Remove the `cspHeader` variable and the entire `async headers()` function from `next.config.ts`, leaving only the `images` config and any other non-header config.

**Done:** `next.config.ts` contains no `headers()` function and no `cspHeader` variable.

### Task 3: Build verification
type="auto"

Run `npm run build` to verify the project builds successfully with the middleware in place and headers removed from config.

**Done:** Build completes without errors.

## Verification

1. `src/middleware.ts` exists and sets CSP, X-Frame-Options, X-Content-Type-Options, Referrer-Policy
2. `next.config.ts` has no `headers()` function
3. `npm run build` succeeds

## Success Criteria

- All security headers served from middleware
- No header duplication (single source of truth)
- Build passes
