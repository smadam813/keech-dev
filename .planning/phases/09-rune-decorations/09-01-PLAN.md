**Part A: RuneDivider component**

Create `src/components/runes/rune-divider.tsx` as a server component (NO 'use client'):

```tsx
import { ELDER_FUTHARK, type Rune } from './rune-config'
import { cn } from '@/lib/utils'

interface RuneDividerProps {
  rune?: Rune
  className?: string
}

export function RuneDivider({
  rune = ELDER_FUTHARK.dagaz,
  className
}: RuneDividerProps) {
  return (
    <div
      className={cn('flex items-center gap-4 my-8', className)}
      role="separator"
    >
      <div className="flex-1 h-[2px] bg-foreground" />
      <span
        aria-hidden="true"
        className="font-display font-bold text-2xl text-accent select-none leading-none"
      >
        {rune.char}
      </span>
      <div className="flex-1 h-[2px] bg-foreground" />
    </div>
  )
}
```

Key design decisions:
- Default rune is Dagaz (dawn/new beginnings) — symbolically appropriate for transitions
- Uses `font-display font-bold` to render via Norse font (per user decision — Norse font contains runic glyphs)
- Teal accent color (`text-accent`) for the rune character — cohesive with existing design system
- `aria-hidden="true"` on the rune span for accessibility (RUNE-05)
- `role="separator"` on the container for semantic HTML
- `select-none` prevents accidental text selection of decorative rune
- Accepts optional `rune` prop to use context-specific runes (e.g., Kenaz for blog dividers)

**Part B: Rune bullet CSS for .prose ul**

In `src/app/globals.css`, within the existing `/* Lists */` section of the `.prose` block (inside the `@layer components` section), replace the existing `.prose ul` rule:

Replace:
```css
  .prose ul {
    list-style-type: disc;
  }
```

With:
```css
  .prose ul {
    list-style: none;
    padding-left: 1.75em;
  }

  .prose ul > li {
    position: relative;
  }

  .prose ul > li::before {
    content: '\16A8';  /* Ansuz rune — wisdom/communication */
    font-family: var(--font-display);
    font-weight: 700;
    color: var(--color-accent);
    position: absolute;
    left: -1.5em;
    font-size: 0.75em;
    line-height: inherit;
  }
```

Also add `role="list"` support note as a CSS comment — Safari strips list semantics when `list-style: none` is used. The executor should be aware that any `<ul>` elements rendered in .prose from MDX will need `role="list"` if VoiceOver semantics matter. However, since MDX-generated lists are standard HTML `<ul>` elements and we're using `::before` (not removing the `<li>` structure), and the rune is purely decorative, this is acceptable. Add a comment noting the Safari consideration.

Ensure nested lists (`li > ul > li::before`) also get rune bullets — the existing `.prose li > ul` rule handles nesting margins.

Key decisions:
- `::before` pseudo-element approach (100% browser support) instead of `@counter-style` (94%) per research recommendation
- Same rune (Ansuz) for all blog list bullets — consistent, not distracting
- `font-weight: 700` (bold) because Norse font regular weight is too thin at small sizes (per Phase 7 decision)
- `font-size: 0.75em` for accent-level prominence — visible but secondary to content
- Teal accent color matches divider rune color for visual cohesion
