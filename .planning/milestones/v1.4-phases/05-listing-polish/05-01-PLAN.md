Create two new files:

**1. `src/app/api/views/route.ts`** — Batch GET endpoint:
- Export `const dynamic = 'force-dynamic'` to prevent build-time caching
- Export `async function GET(request: Request)` that:
  - Reads `slugs` query parameter from URL, splits on comma, filters empty strings
  - Returns `{ counts: {} }` if no slugs provided
  - Builds Redis keys as `views:${slug}` for each slug (matching existing key prefix convention)
  - Calls `redis.mget<(number | null)[]>(...keys)` for single Redis round-trip
  - Maps results back to `{ counts: { slug1: N, slug2: N } }` with `?? 0` for null values
  - Wraps in try/catch: on error, `console.error('[views] Redis error:', error)` and return 500 JSON `{ error: 'Failed to fetch view counts' }` (matches existing error pattern in `[slug]/route.ts`)
- Import `redis` from `@/lib/redis` (same pattern as existing route)

**2. `src/lib/views.ts`** — Shared formatting utility:
- Export `function formatViewCount(count: number): string` that:
  - Formats with `count.toLocaleString()` for locale-aware separators (e.g., "1,234")
  - Appends singular/plural label: `count === 1 ? 'view' : 'views'`
  - Returns formatted string like `"1,234 views"` or `"1 view"`
- This extracts the inline logic currently at line 57 of view-counter.tsx
