<task type="auto">
  <name>Task 2: Stabilize mobile nav and footer positioning</name>
  <files>
    src/components/layout/mobile-nav.tsx
    src/components/layout/footer.tsx
  </files>
  <action>
    **In src/components/layout/mobile-nav.tsx (line 20):**
    Add `transform-gpu` class to the nav element's className. This promotes the element to its own compositor layer, preventing jitter during iOS scroll momentum. The className should become:
    `"fixed bottom-0 left-0 right-0 z-50 md:hidden bg-background border-t-[3px] border-foreground transform-gpu"`

    **In src/components/layout/footer.tsx (line 11):**
    Replace the static `pb-24` with a dynamic calculation that respects safe-area-inset-bottom. Change the footer className from:
    `"bg-foreground text-background pt-8 pb-24 md:py-8 mt-auto"`
    to:
    `"bg-foreground text-background pt-8 md:py-8 mt-auto"`

    Then add an inline style to the footer element:
    `style={{ paddingBottom: 'calc(6rem + env(safe-area-inset-bottom))' }}`

    This combines the base 6rem (96px, matching pb-24) with the device's safe area inset. On desktop, safe-area-inset-bottom is 0, so it degrades gracefully. The md:py-8 still overrides for desktop via Tailwind.

    Also add a media query condition: only apply the inline paddingBottom on mobile. Use a className approach instead - add a wrapper div or use CSS.

    Actually, simpler approach: Keep pb-24 for mobile only and let md:py-8 handle desktop:
    - Use `pb-[calc(6rem+env(safe-area-inset-bottom))]` for mobile
    - This is complex in Tailwind, so use inline style with media query logic

    Simplest solution: Use inline style that's always applied but md:py-8 CSS will override on desktop:
    ```tsx
    <footer
      className="bg-foreground text-background pt-8 md:py-8 mt-auto"
      style={{ paddingBottom: 'max(6rem, calc(6rem + env(safe-area-inset-bottom)))' }}
    >
    ```

    But Tailwind's md:py-8 won't override inline styles. So we need a different approach.

    Best approach: Use CSS custom property in globals.css and reference it:
    In globals.css @layer base, add to the existing html rule or create new:
    ```css
    :root {
      --footer-pb-mobile: calc(6rem + env(safe-area-inset-bottom));
    }
    ```

    Then in footer.tsx, use a responsive approach:
    - On mobile: padding-bottom uses the custom property
    - On desktop (md:): padding-bottom is 2rem (py-8)

    Actually simplest: just use the inline style for mobile and let the component handle it:

    ```tsx
    <footer className="bg-foreground text-background pt-8 pb-[calc(6rem+env(safe-area-inset-bottom))] md:py-8 mt-auto">
    ```

    Tailwind v4 should support this arbitrary value syntax with env(). If not, fall back to inline style approach with a useEffect for SSR safety or just accept that inline style will be used with a comment.
  </action>

    Grep for "transform-gpu" in mobile-nav.tsx - should find it.
    Grep for "safe-area" in footer.tsx - should find env(safe-area-inset-bottom).
  </verify>
  <done>

  </done>
