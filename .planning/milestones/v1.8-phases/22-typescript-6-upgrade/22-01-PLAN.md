  <action>
Per D-02, perform the upgrade as a single atomic step:

1. Install TypeScript 6.0.2:
   ```bash
   npm install --save-dev typescript@^6.0.2
   ```

2. Run the official ts5to6 migration tool per D-01:
   ```bash
   npx @andrewbranch/ts5to6@1.1.1
   ```
   This tool handles baseUrl and rootDir migrations. Expected to be a no-op for this project (no baseUrl set, noEmit: true makes rootDir irrelevant). Run it anyway to catch edge cases.

3. Clean up deprecated options in tsconfig.json per D-03:
   - REMOVE the `"esModuleInterop": true` line entirely (always-on in TS6, keeping it generates a deprecation warning)
   - KEEP all other options exactly as they are:
     - `"target": "ES2022"` — keep explicit value (TS6 defaults to es2025 but explicit value is preserved; no benefit to changing since noEmit: true)
     - `"module": "esnext"` — already the TS6 default, keep explicit
     - `"moduleResolution": "bundler"` — already the TS6 default, keep explicit
     - `"skipLibCheck": true` — keep per D-05
     - `"types": ["vitest/globals"]` — keep explicit (TS6 defaults types to [], but explicit value preserved)
     - All other options unchanged

4. Quick compiler check:
   ```bash
   npx tsc --noEmit
   ```
   If this fails with errors on CSS side-effect imports (e.g., `import "./globals.css"` in layout.tsx or global-error.tsx), add `"noUncheckedSideEffectImports": false` to tsconfig.json compilerOptions per D-04. Next.js provides `declare module '*.css' {}` via next-env.d.ts references, so this should NOT be needed — but check.

   If any other type errors appear per D-08: fix source code directly. Do NOT add @ts-ignore, @ts-expect-error, or weaken strictness. Per D-09: if errors point to node_modules, check for updated @types packages first; skipLibCheck covers library .d.ts files.

The resulting tsconfig.json should be identical to the current one except with the `"esModuleInterop": true` line removed.
